# ペルソナのパネルで決める

ユーザーに選ばせる前に、想定する利用者と専門家のパネル（シミュレーション）に意見を聞いて決める。測れるもの（音質・性能・容量・ライセンスなど）は、パネルではなく測って決める。

## 進め方
1. **パネルを組む**：12人以上。実際の利用者の幅を入れる。
   - 例（子ども向けアプリ）：対象年齢の子ども数人（得意な子・苦手な子・左利き・字が読めない子）、共働きの親、ひとり親、祖父母、その分野の専門家（講師など）、保育士、アクセシビリティに配慮が要る人（弱視・聴覚・ADHD の子の親）、アプリのデザイナー、ストア審査に詳しい人、海外の利用者
2. **開かれた質問にする**：「A と B のどちらがよいか」と二択にしない。「この画面を見てどう感じるか」「困りそうなところは」「どうしたいか」と聞く。作者の好みや期待する答えを質問に入れない。
3. **見せられるものは見せる**：画面ならスクリーンショットやモックの画像を Read で見られる場所に置いて、具体的な箇所を指して答えてもらう。
4. **出力の形**：各人の短い意見、論点ごとの集計（票）と結論、少数意見のうち取り入れるべき点、実装の前に直すべき点。
5. **記録する**：結論を関係する issue にコメントで残す（日付・人数・票）。

## 気をつけること
- 結果には必ず「シミュレーションであり、実在の人の意見ではない」と書く。
- 音・手触り・実機の見え方など、シミュレーションでは確かめられないものは、その限界を書き、実際に確かめる手段（試聴ページ、実機での確認）も添える。
- パネルの票は、取り消しにくい操作（公開・購入・削除・main への push）の許可にはならない。
- ユーザーの好みがすでに分かっているときは、パネルに伝えずに聞き、あとで並べて報告する（パネルを誘導しない）。
- サブエージェントで回す場合も、依頼文に自分の見立てを書かない。
