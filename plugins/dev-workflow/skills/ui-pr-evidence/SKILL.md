# 画面を変える PR には証拠を残す

## まとめて撮る（PR ごとに撮らない）
- シミュレーターでの撮影・録画・UI テストは重く、同時に 1 つしか回せない。画面を変える PR は、PR ごとに撮らず、まとめブランチ（例：`integration/<月日>`）に数本（5〜6 本）取り込んでから、1 回で撮る。
- 1 本ずつの PR の間は、単体テスト・寸法の計算のテスト・プレビューで確かめる。シミュレーターを立ち上げない。
- 画面を変える PR は、まとめブランチを base にして出す。レビューが通ったら、まとめブランチへマージする。画面を変えない PR は、ふだんどおり main へ。
- 撮るのは、直した画面と、影響のある画面だけ。全部の画面は、審査やリリースに出す版の 1 回だけ。
- 撮った画像は、どの PR の証拠かを分けて、各 PR に貼る。最後に、まとめブランチから main への PR を出し、そこには一覧だけを書く。
- まとめブランチの名前・何本で撮るか・main への入れ方は、リポジトリの CLAUDE.md に従う。書いていなければ、上を既定にし、リポジトリの CLAUDE.md に書き足すよう提案する。

## 撮るもの
- 変わった画面と、その前後の画面。操作しないと出ない画面（結果、アラート、時間切れ、設定の奥）も含める。
- ライトとダークの両方。小さい画面と大きい画面（例：iPhone の小さい機種と大きい機種、iPad）。文字サイズ最大の例も 1 枚。ただし、変わった所に関係する組み合わせだけにする。
- 動き・アニメーション・操作の流れが変わるときは動画（シミュレーターの録画など）。

## 変更前と変更後
- 変更前は main から撮る。git worktree に main を出し、撮影用のテストや識別子だけを足して（見た目は変えない）、同じ手順で撮る。前に撮った同じ条件の画像が残っていれば、それを使い、撮り直さない。
- 比較できるように、同じ画面・同じ条件（言語・向き・設定）で並べる。前のテストで変えた設定が残っていないか気をつける（UI テストの起動時に設定を消すなど）。

## 画像を見る量を抑える
画像は 1 枚ごとに大きくトークンを使う（長辺が大きいほど多い）。見る前に、次のようにする。
- **縮めてから見る**：全体の確かめは、長辺 1000px 前後に縮めた写しを見る（macOS なら `sips -Z 1000 in.png --out small.png`）。細部（線の切れ・1px の隙間）は、元の画像からその所だけを切り抜いて見る。元の大きさのまま全体を開かない。
- **並べた 1 枚にする**：変更前と変更後、ライトとダーク、機種違いは、ラベルを付けて 1 枚に並べて（コンタクトシート）見せる。1 枚ずつ何十枚も開かせない。
- **動画のコマは出来事で選ぶ**：1 秒ごとに全部を見せない。場面の区切り（操作・状態の変わり目・最初と最後）のコマを選び、1 枚に並べる。間の動きを確かめたいときだけ、その区間を細かく取る。
- **見直しは 1 回、結果を文字で使い回す**：画像の見直しは 1 つのエージェントに任せ、1 枚ごとの所見を文字で返させる。パネルや 2 回目のレビューには、その文字と、判断に要る数枚（並べた 1 枚）だけを渡す。同じ画像の束を、別のエージェントに最初から開き直させない。
- **直したあとは差分だけ**：撮り直したら、変わった画像だけをもう一度見る。
- メインのセッションでは画像を開かない（開いた画像は会話に残り続けて、コンテキストを使う）。見直しを別のエージェントに任せて、結果を文字で受け取る。

## 見直す
- 見る所：文字の切れ・はみ出し・重なり、隠れたボタン、読めない色の組み合わせ、ダークモードで消える線、意図しない並べ方。
- 縦の枠に横向きの中身が入った画像は、見せる前・貼る前に回す（macOS なら `sips --rotate`）。
- 自動の監査（アクセシビリティ監査など）だけでは足りない。
- 問題があれば直して撮り直してから PR に載せる。

## 載せ方
- 画像と動画は `gh pr create`／`gh pr edit`／`gh pr comment` の `--attach './x.png#説明'`（gh 2.102 以降）で添付し、本文に `![説明](./x.png)` と書く。本文の参照が添付の URL に書き換わる。`<img src>` は書き換わらず、添付が本文の末尾に足される。
- 貼るのは元の大きさの画像でよい（人が見るもの）。縮めるのは、エージェントが見る写しだけ。
- 作ったあとで、本文の画像が `user-attachments/assets/…` に書き換わり、数が合っているかを確かめる。書き換わらず末尾に足されたときは、本文を手で直す。
- 画像用のブランチに置いて `blob/…?raw=true` で参照する方法は、非公開のリポジトリでは表示されない（空欄になる）。使わない。
- 変更前／変更後を並べ、何が変わったかを短く添える。

## 見た目の不具合を issue にするとき
- 撮影や見直しで見つけた崩れを issue にするときは、その画像を必ず貼る：`gh issue create`／`gh issue comment` の `--attach './x.png#説明'` と、本文の `![説明](./x.png)`。会話で画像を開かなくても貼れる。貼ったあとで、本文の画像が `user-attachments/assets/…` に書き換わったかを確かめる。

## マージの前に
- パネル（`persona-panel`）に見せたあとで見た目が変わったら、最終の画面でもう一度見せる（変わった所だけを並べた 1 枚で）。
