# 画面を変える PR には証拠を残す

## 撮るもの
- 変わった画面と、その前後の画面。操作しないと出ない画面（結果、アラート、時間切れ、設定の奥）も含める。
- ライトとダークの両方。小さい画面と大きい画面（例：iPhone の小さい機種と大きい機種、iPad）。文字サイズ最大の例も1枚。
- 動き・アニメーション・操作の流れが変わるときは動画（シミュレーターの録画など）。

## 変更前と変更後
- 変更前は main から撮る。git worktree に main を出し、撮影用のテストや識別子だけを足して（見た目は変えない）、同じ手順で撮る。
- 比較できるように、同じ画面・同じ条件（言語・向き・設定）で並べる。前のテストで変えた設定が残っていないか気をつける（UI テストの起動時に設定を消すなど）。

## 見直す
- 1枚ずつ目で見る：文字の切れ・はみ出し・重なり、隠れたボタン、読めない色の組み合わせ、ダークモードで消える線、意図しない並べ方。画像の見直しを別のエージェントに任せて、結果を文字で受け取ってもよい（開いた画像は会話に残り続けてコンテキストを使う）。
- 縦の枠に横向きの中身が入った画像は、見せる前・貼る前に回す（macOS なら `sips --rotate`）。
- 自動の監査（アクセシビリティ監査など）だけでは足りない。
- 問題があれば直して撮り直してから PR に載せる。

## 載せ方
- 画像と動画は `gh pr create`／`gh pr edit`／`gh pr comment` の `--attach './x.png#説明'`（gh 2.102 以降）で添付し、本文に `![説明](./x.png)` と書く。本文の参照が添付の URL に書き換わる。`<img src>` は書き換わらず、添付が本文の末尾に足される。
- 作ったあとで、本文の画像が `user-attachments/assets/…` に書き換わり、数が合っているかを確かめる。書き換わらず末尾に足されたときは、本文を手で直す。
- 画像用のブランチに置いて `blob/…?raw=true` で参照する方法は、非公開のリポジトリでは表示されない（空欄になる）。使わない。
- 変更前／変更後を並べ、何が変わったかを短く添える。

## 見た目の不具合を issue にするとき
- 撮影や見直しで見つけた崩れを issue にするときは、その画像を必ず貼る：`gh issue create`／`gh issue comment` の `--attach './x.png#説明'` と、本文の `![説明](./x.png)`。会話で画像を開かなくても貼れる。貼ったあとで、本文の画像が `user-attachments/assets/…` に書き換わったかを確かめる。

## マージの前に
- パネル（`persona-panel`）に見せたあとで見た目が変わったら、最終の画面でもう一度見せる。
